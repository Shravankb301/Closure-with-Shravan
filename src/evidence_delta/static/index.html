The engineering underneath

            
Correctness is the feature.

          

          
The system is deliberately small at the infrastructure layer and uncompromising at the consistency boundary: PostgreSQL transactions, pure derivation, exact dependency reads, and immutable publication.

        


        

          

            SYSTEM INVARIANT
            
The maintained state always matches a full rebuild.

            
Every committed mutation advances only its smallest supported partition. Once queued work settles, the maintained artifacts must be byte-for-byte equivalent to rebuilding from every active assertion.

            
incremental(case, revision n)
== full_rebuild(active_assertions, revision n)

          


          

            
01 / INPUT
Append-only assertions
Source-specific facts remain immutable. Retraction adds a tombstone.

            
02 / IMPACT
Versioned change keys
Fine-grained keys locate only artifacts that actually read changed data.

            
03 / COMPUTE
Fenced durable queue
Leases, claim tokens, bounded retries, and stale-worker rejection.

            
04 / PROOF
Immutable publication
Version, lineage, dependencies, pointer, and success commit together.

          

        


        

          
Crash recovery
Death before commit leaves nothing behind.
A forced worker crash after flush rolls back the version, dependencies, pointer, and job success as one unit.
AUTOMATED: crash-after-flush test

          
Race safety
A stale worker cannot publish old truth.
Dependency versions are locked and compared immediately before publication. Advanced work becomes superseded.
AUTOMATED: compute/publish race test

          
Provenance
Retraction never erases the record.
Derived state changes while original assertions, source locators, and prior artifact versions remain auditable.
LIVE: use Retract source above

          
Concurrency
Four workers claim each job once.
PostgreSQL SKIP LOCKED enables parallel claims while transactional publication preserves at-least-once safety.
CI: PostgreSQL multi-worker test
